# 测试

## 为什么必须有契约测试

上线时踩到的第一个坑：面板跳转回来只报「请求失败」，日志里是 `App not found` ——
**平台注册的是 `xmcp`，应用配的是 `x-mcp`**。两侧单测全绿，因为各自都符合自己对契约的理解。

这类问题有三个共同点：

1. **单测抓不到**——mock 的两边按同一个假设写的，假设本身错了就永远发现不了；
2. **报错信息骗人**——应用把平台的 `message` 当错误码分支，于是「标识不一致」被显示成
   「启动码无效，请回面板重开」，用户拿了新码再试，一模一样地失败；
3. **排查成本高**——要 SSH 上去翻日志才知道哪一步不对。

所以需要一套**跑在真实链路上、并且能指出是哪一方的错**的检查。

## 三层测试，各管什么

| 层 | 跑什么 | 抓什么 | 跑在哪 |
|---|---|---|---|
| 单元 | 每个函数 | 解析、状态机、规则校验、路由选择 | 每次保存，本地 |
| 契约 | 真应用 + 真平台 | 两侧假设不一致 | 每次部署后，CI |
| 端到端 | 假平台 + 真浏览器 | 前端真的能走通 | 改前端后，手工 |

**契约测试是这一层独有的**：它不 mock 任何东西，所以能抓到单元测试因为「假设一致」而
结构性漏掉的问题。

三层各有够不着的地方，**游客路径正好落在中间那条缝里**：

| 层 | 能证明 | 证不了 |
|---|---|---|
| 单元（读源码 / 纯函数） | 规则**存在** | 规则是否真的生效 |
| 契约（真链路） | 落地页匿名可达、业务接口匿名 401、exchange 形状对 | 前端**点了什么才**跳登录 |
| 端到端（真浏览器） | 整条链路真的走通 | —— |

所以「游客可浏览」这个模式要**三层都写**：单测钉规则，契约测保证 S1/S4 不退化，
端到端测用假平台把「未登录 → 点生成 → 跳授权页 → 带 code 回来 → 回到原位」串一遍。

## 契约测试的设计

### 检查项由声明驱动

```js
const target = {
  platformBase: 'https://ai.lesec.top',
  appBase: 'https://canvas.lesec.top',
  key: 'canvas',
  entryPath: '/',
  iconPath: '/icon.svg',
  healthPath: '/api/health',
  protectedPaths: ['/api/session', '/api/projects'],
};
```

不声明 `healthPath` 就跳过 D2，不声明 `protectedPaths` 就跳过 S4。**换一个应用只换这个对象，
不改检查代码** —— 这是「能通用到所有 New API 小程序」的关键。

### 每条检查声明 owner

失败时最有价值的信息不是「哪里坏了」，而是「该谁修」：

| owner | 含义 | 谁修 |
|---|---|---|
| `deploy` | 两侧配置不一致 | 部署的人 |
| `platform` | 平台与自己的契约不一致 | New API 开发组 |
| `app` | 本应用的问题 | 应用侧 |
| `network` | 连不上 | 谁都不怪 |

报告按 owner 汇总，可直接把 `platform` 那一行原样交给平台开发组。

### 检查项

| ID | 检查 | owner |
|---|---|---|
| D1 | 平台注册表里有这个应用标识 | deploy |
| D2 | 应用自报的 `app_key` 与目标一致 | deploy |
| S1 | 落地页可匿名访问且是 HTML | deploy |
| S2 | 落地页声明了 viewport | app |
| S3 | 图标可匿名访问且是图片 | deploy |
| S4 | 业务接口对匿名返回 401 | app |
| C1 | 失败响应带机器可读的 `code` | platform |
| C2 | `code` 不随 `Accept-Language` 变化 | platform |
| C3 | 无效启动码返回契约里的错误码 | platform |
| C4 | exchange 经公网入口仍是 JSON | platform |
| C5 | exchange 失败时不泄露密钥 | app |
| C6 | 应用把平台失败转成自己的错误码 | app |
| C7 | 提示语与真实原因一致 | app |
| **V1** | **`GET /api/apps/:key/options` 存在（401/403，不是 404）** | **platform** |
| **V2** | **exchange 响应带 `grants[]` 且每条有 `id`/`api_key`** | **platform** |
| **V3** | **顶层 `api_key` 等于 `grants[0].api_key`（v1 兼容）** | **platform** |
| **V4** | **应用对外的状态接口不含任何 `sk-`** | **app** |

V1 是判断「线上平台是不是 v3」最省事的一条：`404` 说明这版二进制还没有 v3 路由，
此时应用只能走 v1 单密钥回退，不是应用侧的问题。

几条容易被当成「没必要」的，其实各自抓到过真问题：

- **S2**：少一行 viewport meta，手机浏览器按 980px 布局再缩放，所有 `@media` 断点都不触发。
  桌面浏览器**完全看不出来**。
- **C4**：反代 / WAF / 隧道会在请求到达处理器前把它挡掉，只看状态码看不出来——要看
  `content-type`。
- **C6**：抓到过 **Cloudflare 把源站的 502 改写成自己的纯文本 `error code: 502`**，
  应用写的中文提示根本到不了浏览器。修法是改用 503。
- **C7**：「换个启动码就能好」的情况才允许让用户回面板。其余情况提示语必须指向管理员。

### 检查本身失败 ≠ 契约失败

连不上目标时归为 `network` 并**跳过**，不算失败。否则一次网络抖动会报出一屏假失败。
需要重试（跨境链路实测约 1/3 的连接会失败），重试耗尽才判 `network`。

### 别在测试里 `process.exit()`

`run.mjs` 用 `process.exitCode = …` 而不是 `process.exit()`。后者会在 undici 的 socket
还在关闭时中断，Windows 上触发 libuv 断言（`Assertion failed: !(handle->flags &
UV_HANDLE_CLOSING)`）并以一个看不懂的状态码退出。

## 怎么用同一批检查测本地

`checks.mjs` 刻意不引入任何框架（要能在只有 node 的机器上跑）。同一批检查可以直接
从 vitest 里 import，指向本地起的应用：

```ts
import { runChecks, STATUS } from '../contract/checks.mjs';

const results = await runChecks({ platformBase: standIn, appBase: localApp, key: 'canvas', … });
expect(results.filter((r) => r.status === STATUS.FAIL)).toEqual([]);
```

**并且要用它测自己**：每个检查都要有一条「构造出它该抓的缺陷，断言它抓到了」的测试。
否则检查会腐烂成一串永远绿的摆设。

## 单元测试必须钉住的几条

契约相关的硬约束，光靠契约测试覆盖不到（需要真实用户会话 / 真实多 grant），必须有单测。

### 会话与错误分类

- exchange 失败时响应**不含** `sk-`；
- 402 之后会话**仍然有效**；
- 无 `code` 的失败**不得**被归成某个具体业务错误（否则就是把「配置错了」说成「码无效」）；
- `app.not_found` / `app.disabled` 的提示语**不含**「回面板重新打开」。

### v3 多授权项（本仓库：`service/platform_test.go`）

| 要钉住的 | 退化成什么 |
|---|---|
| `grants` 优先于顶层 `api_key` | 平台升级后应用还在用主 grant 一把梭 |
| 只有顶层 `api_key` 时落成一条 `legacy` grant | 老部署直接不可用 |
| 没有 `id` 的 grant 也能拿到稳定的本地 key | 每次 exchange 都换 key，缓存全失效 |
| 没有 `api_key` 的 grant 被丢弃 | 路由到一张空密钥 |
| 按模型命中对应 grant | 生图请求打到文本密钥，403 |
| 同一模型多条命中时按 priority 排序 | 结果不确定，时好时坏 |
| `legacy`（声明面为空）永远排在声明过模型的 grant 之后 | 兜底项抢走别的 grant 的模型，绕过分组边界 |
| `revoked` 的 grant 不参与路由 | 一直重试一张死密钥 |
| 无 grant 覆盖该模型时**不回退** | 请求被发到未授权的分组 |
| 渠道必须带 `PlatformGrantKey` | 401 降级、排障、用量归属全断 |

### v3 失败矩阵（本仓库：`service/platform_test.go`）

| 要钉住的 | 退化成什么 |
|---|---|
| 只有 401 会 revoke | 402/429 一抖就把用户的授权项全标死 |
| 单条 401 只标这一条（`platformGrantsExhausted` 为假） | 用户删了一张密钥就被登出 |
| **全部** grant 都失效才清会话 | 永远不会登出，用户一直撞 401 |
| 402 不清会话、不换 grant | 换 key 再失败一次，还多打一轮平台 |

### v3 模型目录（本仓库：`service/platform_test.go`）

| 要钉住的 | 退化成什么 |
|---|---|
| 目录 = 各 grant `/v1/models` 的并集去重 | 只看到主 grant 的模型 |
| 单条 grant 拉取失败 → 用它声明的 `models` | 一次抖动就把生图模型从下拉框抹掉 |
| 缓存键包含 grant 集合 | 增删 grant 后继续显示旧模型 |
| 状态接口只回摘要、绝不回 `sk-` | 密钥泄露到浏览器 |

### 游客路径：读页面源码也够用

「游客能看首页、登录门槛在动作上」这一组没有服务端接口可以断言 ——
**它是前端的行为**。契约测试也够不着它（S1 只验「落地页可匿名访问且是 HTML」，
验不了「点了生成才跳登录」）。

所以让单测**读页面源码 + 内联脚本**，把规则逐条钉死。这不是理想的做法，
但对应的 bug 全都在真浏览器里出现，而下面每条都对应一个真实退化：

| 要钉住的 | 退化成什么 |
|---|---|
| `/api/session` 失败时走首页，不是错误页 | 游客打开应用看到一个报错页 |
| 需要身份的动作里有 `requireLogin('generate')` | 用户写完才发现要登录，或者服务端回 401 |
| `requireLogin` 里有 `returnPath` + `intent` + base64 编码 | 登录回来落到首页，用户以为白登一次 |
| `safeReturnPath` 拒绝 `//host`、`/\host`、绝对 URL | `state` 成了开放重定向入口 |
| `decodeState` 里有 `catch` + `return null` | 一个被手改的 `state` 让整页白屏 |
| 页面上**没有** `<form>`，也没有 `/api/session/login` | 摆了一个提交不了任何东西的表单 |
| 页面里**不出现**平台域名，授权地址来自 `/api/session/config` | 换一个部署就要改页面 |

纯函数优先直接测（本仓库 `web/src/lib/platform-auth.test.ts` 就是这种），
能测纯函数就不要去读源码文本。

写法上有个坑：断言用的是源码**文本**，所以自己写的注释也会被匹配到。
`expect(body).not.toContain('innerHTML')` 这种就曾被一句中文注释绊倒 ——
用 `not.toMatch(/\.innerHTML/)` 之类带上下文的模式，而不是裸词。

> 这一层证不了「拇指够得到」—— 它只能证明规则存在。

## 端到端：假平台

契约测试有个够不着的地方：**它无法建立会话**，所以「登录码换会话」「模型调用
真的走了 relay」「多张密钥真的按模型分流」这几步验不到。补法不是去打真平台
（要真用户、真额度、真密钥），而是起一个**假平台**，把整条链路串起来。

假平台要实现契约的用户侧端点 + exchange + relay，并且**忠实复现生产上踩到的行为**：

- 失败是 HTTP 200 + `success:false`，**并且带 `code`**；
- 启动码一次性、5 分钟过期；
- **exchange 返回 `grants[]`**（v3）。至少两种形态各测一遍：
  1. 两条 grant、模型面不重叠 → 断言两个模型分别打到两张密钥；
  2. 两条 grant、同一个模型都声明 → 断言按 priority 选第一条，且失败后能换第二条；
- **relay 的 401 是按密钥的**：只让被单独撤销的那张返回 401，其他 grant 仍然 200。
  这是 v3 最容易写错的地方——假平台如果一撤就全 401，就测不出「单张失效不登出」；
- manual 模式：授权页要有**分组勾选框**，勾几个就签几条 grant。

再加一个**控制面**（`/__issue`、`/__disconnect`、`/__revoke-grant`、`/__state`），
让测试可以主动发码、模拟断开、模拟只撤销一张密钥。
**没有 `/__revoke-grant` 就测不了 v3 最关键的那条语义。**

### 假平台还要有一个授权页

测「游客 → 点生成 → 登录 → 回来接着生成」这条路径，假平台就得有
`GET /apps/authorize?app=…&state=…`：

```js
// 假平台的授权页：一个真的 HTML 页面，上面一个「同意」表单。
// 点它就把 state 原样带回 entry_url，并附上一个由控制面签发的一次性 code ——
// 这正是真平台的行为：应用与 state 都不丢。
// manual 模式还要渲染分组勾选框，勾中的分组决定 exchange 返回几条 grant。
```

要断言的四步，缺一步都测不到真正的问题：

| 断言 | 退化时的表现 |
|---|---|
| 未登录访问首页，看到的是**首页内容**而不是登录提示 | 游客看到一个报错页 |
| 点「生成」→ 浏览器**已经在授权页**且 URL 带 `app=` 与 `state=` | 要么提前拦，要么放任请求走到服务端才 401 |
| 走完授权页回来，地址栏的 `code` **已经没了** | 5 分钟内的凭据留在历史记录里 |
| 回来后**还在原来的页面**（不是首页） | 用户以为白登一次 |

最后一条最容易漏，也最该测：它是「登录白登一次」这个失败的**唯一**回归守卫。

### 这套 e2e 抓到过的真问题

单测**不可能**发现它们，因为每一类都只在「真服务 + 真会话 + 真 HTTP 客户端」
同时在场时才存在：

| 问题 | 表现 | 为什么单测抓不到 |
|---|---|---|
| relay 地址少了 `/v1` | 每次模型调用 404，看起来像模型问题 | 单测里 mock 的 URL 是自己写的，写错一起错 |
| 会话 Cookie 被截断 | exchange 之后的每个请求都 403 | 签名 Cookie 是两个、且值里的 `=` 是 base64 的一部分 |
| 状态端点挂在登录守卫后面 | 最需要它的那个访客（没带启动码的）拿到 403 | 单测直接构造 request 对象，绕过了守卫 |

第三条的教训值得单独记：**「报告状态的端点不能要求它报告的那个状态」。**

### 假平台够不着的地方：界面

还有一类问题**连这套 e2e 也抓不到**，因为它不跑浏览器。实测踩到的：
平台会话下模型列表静默返回空，界面上一直显示内置模型，
用户点「连接」什么也不发生 —— 而 e2e 直接 POST `/status`，一路全绿。

要抓这类问题只有一条路：**用假平台 + 真浏览器，走一遍用户真正会走的动作**，
并断言**用户最终看到什么**，不是某个函数被调用过。

| 断言 | 抓的是什么 |
|---|---|
| 登录后下拉框里出现的是**平台白名单里的模型** | 服务端的静默失败（TDZ 报错被吞成空 `200 {}`） |
| 点「连接」**真的发出了请求** | 前端守卫在发请求之前就 `return` 了 |
| 全程**没有页面错误、没有未捕获异常** | async handler 里的抛出不会出现在响应里 |

三条各自对应一个真实退化，而且互不覆盖 —— 只测第一条的话，
「Connect 根本没发请求」照样漏过去。

### v3 在 e2e 层要额外断言的

| 断言 | 退化时的表现 |
|---|---|
| 模型选择器里是**所有 grant 的并集** | 只显示主 grant 的模型，用户以为生图不支持 |
| 两个模型分别生成，服务端日志里的渠道名不同（带授权项名/分组） | 全部打到同一张密钥，另一张白签发 |
| 只撤掉一条密钥（控制面）→ 另一个模型的生成**仍然成功** | 一张失效就登出，用户被踢回授权页 |
| 撤掉全部密钥 → 下一次生成 401 且会话清空 | 永远不登出，用户一直撞 401 |
| manual 模式只勾一个分组 → 另一个分组的模型**不在**选择器里 | 勾选没生效，等于给了全部 |

参考实现：`sillytavern-newapi-app/tools/fake-platform.mjs` +
`tools/e2e-newapi.mjs`（`npm run test:newapi`）；
真浏览器那一层见同仓库 `final-verify*.mjs` 的驱动方式
（Playwright，`chromium.launch()` 后 `page.on('pageerror')`）。
